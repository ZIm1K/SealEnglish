## 1. Що це

Конвеєр, який через день готує **пакет із 5 матеріалів** (TikTok-історія, навчальне відео для
Stories, пости для Threads, Telegram та Instagram), чекає на затвердження власника в кабінеті,
а потім виробляє медіа й надсилає результат у Telegram.

```
Cloud Scheduler ─────────▶ Cloud Run Job «seal-farm» ─────▶ Supabase: таблиці, кеш, обкладинки
  pack    щодня 06:00           ▲          │                    ▲            │ тригер на статус
  work    кожні 30 хв 06–23:30  │          ├──▶ Google Drive    │ кабінет    ▼
  backup  понеділок 04:00       │          │     (відео, копії) │ /app/content/  Edge Function
                                │          ▼                    │                «farm-kick»
                                │   Claude · ElevenLabs · Gemini · Groq ──▶ Telegram     │
                                └────────────────────────────────────────────────────────┘
                                         затвердження одразу запускає job
```

| Складова | Де | Що робить |
|---|---|---|
| Cloud Run Job `seal-farm` | Google Cloud, проєкт `bond-bot-494410`, `europe-west1`, 2 vCPU / 4 ГБ, тайм-аут 60 хв | Контейнер з фермою ([Dockerfile](Dockerfile)); команда за замовчуванням — `work` |
| Scheduler `seal-farm-pack` | `0 6 * * *`, Europe/Kyiv | Будить job з аргументом `pack`; сама ферма пропускає запуск, якщо останній пакет молодший за 30 годин — виходить ритм «через день» |
| Scheduler `seal-farm-work` | `*/30 6-23 * * *` | `work`: рухає пакет, що чекає на batch, переписує, виробляє, повторює після збоїв |
| Scheduler `seal-farm-backup` | `0 4 * * 1` | `backup`: копія таблиць на Google Drive |
| Edge Function `farm-kick` | Supabase | Запускає job одразу після затвердження (викликається тригером бази) |
| Supabase `nivxzpsstjphxkodhjzu` | таблиці `content_runs`, `content_ideas`, `content_items`, `content_posts`; бакет `content`; `app_settings`; Vault | Дані, кеш, обкладинки, налаштування, секрети |
| Google Drive | акаунт школи, тека «Seal English — контент-ферма» | Готові відео (`Відео/РРРР-ММ`), резервні копії |
| Кабінет | сайт, `/app/content/` ([page.tsx](../src/app/app/content/page.tsx), [content-editor.tsx](../src/components/app/content-editor.tsx)) | Редагування й затвердження |
| Деплой ферми | [scripts/deploy-cloud.sh](scripts/deploy-cloud.sh) | Збирає образ з робочої теки, оновлює job і розклади |

Три окремі канали доставки коду, і жоден не тягне за собою інший:
`git push` оновлює лише сайт; ферму в хмарі оновлює `deploy-cloud.sh` (бере файли з робочої теки
разом з незакоміченими змінами); Edge Functions деплояться окремо.

## 2. Як проходить матеріал

### 2.1 Пакет (`pack`)

| # | Крок | Файл | Чим |
|---|---|---|---|
| 1 | Перевірка ритму: останній пакет старший за 30 год? | [src/cli.ts](src/cli.ts), `hoursSinceLastPack()` | — |
| 2 | Сирі сигнали: Google Trends UA і US (RSS), YouTube UA (якщо є ключ) | [src/trends/sources.ts](src/trends/sources.ts) | безкоштовно |
| 3 | Звіт трендів — до 5 веб-пошуків | [src/plan.ts](src/plan.ts) → `research()` у [src/llm.ts](src/llm.ts) | Sonnet 5.5 + `web_search_20250305`, наживо |
| 4 | Сировина для історій: із банку (`app_settings.content_farm_story_bank`), якщо він молодший за 4 дні; інакше нове дослідження | [src/plan.ts](src/plan.ts) | Sonnet 5.5 + пошук |
| 5 | Попередження, якщо в ElevenLabs менше 5000 символів | [src/media/eleven.ts](src/media/eleven.ts) | — |
| 6 | **Batch 1 «ideas»**: 6 ідей (2 історії + рубрики) | [src/pack.ts](src/pack.ts), `ideateCall()` | Opus 5.5, effort high, −50% |
| 7 | Вибір: найкраща історія, найкраща рубрика, 3 ідеї для постів | `pickPackIdeas()` | — |
| 8 | **Batch 2 «drafts»**: сценарій історії, сценарій навчального відео, три пости | `storyCall()`, `scriptCall()`, `postsCall()` | Opus 5.5, −50% |
| 9 | **Batch 3 «edits»**: редактор-хуманізатор для кожного з трьох | `humanizeCall()` | Sonnet 5.5, −50% |
| 10 | Збереження зі статусом `script`, одне повідомлення в Telegram | `finish()` у [src/pack.ts](src/pack.ts) | — |

**Чому три batch-і, а не один.** Кроки залежать один від одного: сценарій пишеться за ідеєю,
редактор править сценарій. Batch API відповідає асинхронно, тому пакет — машина станів, збережена
в `content_runs.state` (етап, id batch-у, ідеї, чернетки, рядки вартості). Запуск чекає на batch до
`batch_wait_seconds` (4 хв); якщо не дочекався — виходить, а наступний `work` продовжує з того ж
місця. Щоб два запуски не рухали пакет одночасно, є `content_runs.locked_until`.

**Запасні шляхи.** Запит, який у batch-і впав, отримав відмову чи не пройшов схему, одразу
повторюється наживо. Етап, що не відповів за `batch_max_hours` (3 год), скасовується, і його виклики
робляться наживо — ранок важливіший за знижку. `pack --live` взагалі обходить Batch API;
`custom` і `produce` завжди працюють наживо, бо там людина чекає.

Медіа на цьому етапі не створюється — лише тексти.

### 2.2 Виробництво (`work`)

Запускається тригером одразу після затвердження і тиком кожні 30 хв.

1. **Пакет**, що чекає на batch, рухається далі (`advancePack`).
2. **Переписування.** `script_rewrite` → `rewriteWithNote()` → назад у `script`.
3. **Виробництво.** `approved` забирається атомарно (`claimItem`: `approved → rendering`).

Для **історії**:

| Крок | Як | Чим |
|---|---|---|
| Узгодження підписів, якщо репліки правили вручну | `refreshCaptions()` у [src/script.ts](src/script.ts) | Sonnet 5.5, ≈ $0.006 |
| Озвучка кожної репліки голосом персонажа, з таймінгами слів | [src/media/tts.ts](src/media/tts.ts), [eleven.ts](src/media/eleven.ts) | ElevenLabs `eleven_v4`; запасні рушії вимкнено (`tts_fallback`) |
| Таймінги слів, якщо рушій їх не дав | [src/media/align.ts](src/media/align.ts) | Groq Whisper |
| Фон кожної локації, до 4, по 3 паралельно | [src/media/images.ts](src/media/images.ts), [gemini.ts](src/media/gemini.ts) | Gemini 3.1 Flash Lite Image |
| Де голова персонажа фону | [src/media/locate.ts](src/media/locate.ts) | Sonnet 5.5 з картинкою |
| Музика й звуки | [src/media/music.ts](src/media/music.ts), [sfx.ts](src/media/sfx.ts) | генеруються кодом |
| Рендер 1080×1920, H.264 crf 17, і окремий кадр обкладинки | [src/render.ts](src/render.ts), [remotion/Story.tsx](remotion/Story.tsx) | Remotion |
| Відео → Google Drive, обкладинка → Supabase, статус `review`, Telegram | [src/drive.ts](src/drive.ts), [src/store.ts](src/store.ts), [src/notify.ts](src/notify.ts) | — |

Порядок не випадковий: спершу голос (без нього відео не випускається), потім фони, потім рендер —
так збій зупиняє виробництво до того, як витрачено гроші на наступний крок.

Сілі в кадр не генерується: він накладається з готових рендерів `public/mascot3d`.

**Навчальне відео** — усі репліки озвучує Сілі, один фон плюс до двох картинок сцен
([remotion/Short.tsx](remotion/Short.tsx)). **Пости**: Threads — нічого; Telegram — картинка 4:5;
Instagram — фон плюс картка з текстом ([remotion/IgCard.tsx](remotion/IgCard.tsx)).

### 2.3 Статуси `content_items`

```
script ──затвердити──▶ approved ──▶ rendering ──▶ review (готово)
   │                      ▲             │
   │                      └─тимчасовий──┘  attempts+1, до production_attempts (3)
   │                        збій            далі ──▶ failed (можна затвердити ще раз)
   ├──переписати з коментарем──▶ script_rewrite ──▶ rewriting ──▶ script
   └──відхилити──▶ rejected
```

«Тимчасовий збій» — це HTTP 408 / 429 / 5xx або мережева помилка в тексті винятку
(`isTransient` у [src/media/retry.ts](src/media/retry.ts)). Усередині одного запуску вже є повтори
з паузами 4 / 12 / 36 с; автоповтор між запусками покриває довші збої. Помилки, яких чекання не
виправить (невірний ключ, закінчились кредити), одразу дають `failed`.

## 3. Кеш

[src/cache.ts](src/cache.ts) зберігає в бакеті `content/cache/` результати, ключ — хеш того, що їх породило:

| Що | Ключ | Наслідок |
|---|---|---|
| Репліка (аудіо + таймінги) | провайдер, модель, голос, темп, текст, манера | після правки однієї репліки переозвучується лише вона |
| Картинка | провайдер, моделі, промпт, стиль, формат | той самий фон не оплачується двічі |
| Позиція голови | хеш самої картинки + бік | для закешованого фону пошук голови безкоштовний |

Перерендер після збою коштує $0, якщо тексти й промпти не змінювались. Аудіо від запасного
рушія в кеш не потрапляє.

Кеш промптів Claude **не використовується**: у кожного виклику своя схема відповіді, а вона
входить у кешований префікс, тому мітка лише додавала 25% до ціни входу (виміряно 4 жовтня).

## 5. Скільки це коштує

Джерело — власний облік ферми (`content_items.cost_breakdown`) і сторінка цін Anthropic, звірена
4 жовтня 2026: Opus 5.5 — $4 / $20 за 1 млн токенів, Sonnet 5.5 — $2 / $10, веб-пошук — $10 за
1000, Batch API — половина ціни токенів.

| Рядок | Було (2–4 жовтня, виміряно) | Стало |
|---|---|---|
| Дослідження трендів | ≈ $0.11, без результатів | $0.11, з джерелами |
| Дослідження історій | ≈ $0.14 щопакета, без результатів | $0.14 раз на три пакети |
| 6 ідей | ≈ $0.20 | ≈ $0.10 (batch) |
| Сценарій історії + редактор | $0.14–0.18 + $0.06 | ≈ $0.09 (batch, без кеш-мітки й крос-постів) |
| Сценарій навчального відео + редактор | $0.12 | ≈ $0.05 (batch) |
| Три пости | $0.11 | ≈ $0.05 (batch) |
| Озвучка історії / навчального відео | $0.04–0.05 / $0.14 | без змін |
| Фони | $0.034 кожен, до 6 | $0.034 кожен, до 4 |
| Пошук голови | $0.007–0.011 | $0.004–0.006 |
| Узгодження підписів | не було | $0.006, лише після ручної правки |

Колонка «стало» для batch-рядків — розрахунок (половина виміряної ціни мінус прибрані поля);
фактичні цифри першого batch-пакета з'являться в `cost_breakdown` його матеріалів.

**Пакет: було ≈ $1.4, очікувано ≈ $0.9. Місяць (15 пакетів): ≈ $20 → ≈ $13–14.**

## 7. Що свідомо не зроблено

| Тема | Стан |
|---|---|
| Скорочена бренд-біблія, ідеї на effort medium, редактор повертає лише правки | Власник обрав «з порівнянням до / після»; порівняння ще не зроблено — див. [PLAN.md](PLAN.md) |
| Аудіозаписи уроків на Drive | Нема чого переносити: `ai-transcribe` видаляє аудіо одразу після транскрипції, бакет `lesson-audio` порожній |
| Архів журналів ферми | `content_runs` займає 136 КБ; ці рядки потрапляють у резервну копію |
| Видалення старих відео із Supabase | Команда `storage-cleanup --yes` — запускає власник |
| Автопостинг (етап 2) | Не збудований; таблиця `content_posts` порожня. Приватні файли Drive не підходять як публічний URL для Instagram і Threads — для автопостингу відео доведеться тимчасово класти в публічний бакет |

Перевірено й відкинуто: спільний кешований префікс між викликами (не читається через різні схеми
відповіді) і кешування всередині пошукового циклу (модель робить усі пошуки одним колом).

| Якість не має автоматичної перевірки | Єдиний контроль — перегляд власником. Зміни промптів і моделей без порівняння не вмикаються |
| Програвач Drive у кабінеті | Файли приватні: працює лише в браузері, де власник увійшов у Google-акаунт школи; сторонні cookie в iframe можуть бути заблоковані — тоді рятує кнопка «Відкрити на Google Drive» |
| Резервна копія — це експорт даних | JSON таблиць без схеми, без Vault і без файлів із бакетів; містить персональні дані учнів, лежить на приватному Drive |
| Баланс Gemini | 3 жовтня кредити закінчились; ферма про це дізнається лише з помилки |
| Бакет `content` публічний | Обкладинки й картинки постів відкриваються за прямим URL, якщо знати шлях |
| `farm-kick` тримає ключ сервісного акаунта | Ключ має право лише запускати цей job; лежить у Vault |
| Remotion | Безкоштовний до 3 людей у компанії; зараз власник один |
| Тестів немає | Є лише `npm run typecheck`; поведінку перевірено ручними прогонами |

## 9. Діагностика

| Що подивитись | Де |
|---|---|
| Журнал запуску, звіти трендів, стан пакета | `content_runs.log`, `.web_report`, `.state` |
| Вартість і токени кожного кроку (`batch: true` — зі знижкою) | `content_items.cost_breakdown` |
| Причина збою і номер спроби | `content_items.review_note`, `.attempts`; також кабінет і Telegram |
| Журнал хмарного запуску | `gcloud logging read 'resource.type="cloud_run_job" AND resource.labels.job_name="seal-farm"' --project bond-bot-494410` |
| Помилки `farm-kick` | таблиця `error_log`, `source = 'farm-kick'` |
| Банк історій | `app_settings`, ключ `content_farm_story_bank` |

Ознаки проблем у повідомленнях Telegram: «⚠ веб-пошук не дав результатів», «⚠ дослідження
впало», «без редакторського проходу», «❌ Не вдалося виробити», «❌ Пакет не зібрано».
