# Seal English — сценарії тестування (технічний пілот)

**Мета:** перевірити, що платформа технічно працює від початку до кінця на кількох реальних учнях: розклад, ДЗ, сповіщення, Telegram, ШІ, виплати. Це перевірка стабільності, а не методики.

**Тривалість:** 1–2 тижні. **Учасники:** 3–5 учнів, 1–2 викладачі, менеджер, адміністратор.

## Щоденний моніторинг (адміністратор, 5 хв)

1. **Адмінка → «Стан системи»:** помилки за 24 год, невдалі доставки Telegram. Нове — розібрати.
2. **`/app/ai/`:** витрати за день (очікувано < $1 на пілоті), кількість практик, сесії з прапорцем.
3. **Відмічені практики** — переглянути й закрити.

### Що записується і де

| Подія | Де зберігається |
|---|---|
| Будь-яка непередбачена помилка функцій (API, бот, Google Meet, ШІ, облік витрат) | `error_log` → «Стан системи» (зберігається 30 днів) |
| Сповіщення і доставка в Telegram (статус, спроби, текст помилки) | `notifications` (`tg_status`, `tg_attempts`, `tg_error`) |
| Кожен виклик ШІ: модель, токени, кеш, вартість, користувач | `ai_usage` → `/app/ai/` |
| Діалоги з тренером | `practice_turns` (90 днів), підсумки — `practice_sessions` |
| Воронка лідів, пробні | `lead_events` |
| Оцінки ризику | `risk_scores` (120 днів) |
| Детальні логи функцій | Supabase Dashboard → Edge Functions → Logs |

### SQL для швидкої перевірки (Supabase → SQL Editor)

```sql
-- помилки за добу
select created_at, source, message, context from error_log
where created_at > now() - interval '24 hours' order by created_at desc;

-- проблеми з доставкою в Telegram
select created_at, kind, tg_status, tg_attempts, tg_error from notifications
where tg_status = 'failed' order by created_at desc limit 20;

-- витрати ШІ по днях і функціях
select created_at::date, feature, count(*), round(sum(cost_usd), 3) usd
from ai_usage group by 1, 2 order by 1 desc, 4 desc;

-- чернетки перевірки ДЗ, що застрягли або впали
select submission_id, status, error, updated_at from submission_ai_reviews
where status in ('pending', 'failed') and updated_at < now() - interval '5 minutes';
```

## Критерії успіху пілоту

- Жодної помилки, через яку учень чи викладач не зміг виконати дію.
- ≥ 95 % повідомлень у Telegram доставлено (крім тих, хто заблокував бота).
- Чернетки ШІ з'являються для ≥ 95 % зданих ДЗ, не пізніше ніж за 2 хв.
- Учні ніколи не бачать чернеток ШІ та чужих персональних даних.
- Витрати ШІ в межах лімітів; немає «зависання» чернеток у `pending`.
