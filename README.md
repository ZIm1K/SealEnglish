# Seal English 🦭📘

Сайт і платформа онлайн-школи англійської: маркетинговий лендинг, особисті кабінети (учень / викладач / менеджер / адміністратор), розклад з автоматичним Google Meet, домашні завдання, матеріали, CRM заявок на пробний урок, Telegram-бот і ШІ-модуль «викладач + ШІ».

Технічна документація та бізнес-план v2.0 — джерело вимог (FR/NFR/ADR у коментарях коду посилаються на них).

## Архітектура

| Шар | Технології |
| --- | --- |
| Фронтенд | Next.js 16 (App Router, **static export** → `out/`), React 19, Tailwind CSS 4, Motion, Radix UI, TanStack Query |
| Хостинг | Wasmer Edge — роздає статичний `out/` (автоматичне визначення Next.js) |
| Дані й авторизація | Supabase: Postgres + RLS, Auth, Storage, Realtime, Vault, pg_cron, pg_net |
| Серверна логіка | Supabase Edge Functions (Deno) у `supabase/functions` |
| ШІ | Claude (Anthropic SDK) через єдиний модуль `supabase/functions/_shared/ai.ts` |
| Маскот | SVG-риґ `src/components/mascot/Seal.tsx`, геометрія генерується з референсу скриптом `design/mascot/build_rig.py` |

### Edge Functions

| Функція | Що робить |
| --- | --- |
| `lead` | Приймає заявку з сайту (валідація, honeypot, rate limit); за увімкненого тесту рівня видає одноразове посилання |
| `telegram` | Webhook бота: запис на пробний, картки заявок для менеджерів, розклад, ДЗ, прив'язка акаунта, згода батьків на звіти, нічні ШІ-відповіді |
| `notify` | Доставляє сповіщення в Telegram (з повторами), нагадування лідам про пробний, щотижневі звіти батькам |
| `schedule` | Уроки й серії з Google Meet, перенесення, зміна викладача/тривалості, скасування; пробні міні-групи до 4 лідів |
| `admin` | Акаунти, перетворення заявки на учня, інтеграції (Telegram, Google, ключ ШІ), налаштування ШІ, ставки оплати викладачів |
| `google-oauth` | Підключення акаунта Google школи (Calendar + Meet) |
| `ai-review` | Чернетка відгуку й оцінки ДЗ (текст, фото, PDF) — лише для викладача (FR-13) |
| `ai-lesson` | Нотатки викладача → лексика, граматика, помилки (FR-11) |
| `ai-tutor` | Текстовий тренер Сілі зі стрімінгом (SSE), лімітами й модерацією (FR-14, FR-17) |
| `ai-risk` | Пояснення ризику відтоку для менеджера (FR-19, фаза 2) |
| `ai-level-test` | Тест рівня для ліда: 20 питань + письмо з оцінкою ШІ (FR-22, фаза 3) |

Сповіщення працюють за схемою outbox: тригери в БД пишуть у `notifications`, звідти pg_net миттєво викликає `notify`. Невдала доставка повторюється до 3 разів; збої й помилки функцій видно адміністратору в **Інтеграції → Стан системи** (`error_log`, `admin_health()`). Нагадування за годину до уроку (учням, викладачу й лідам пробного) і за добу до дедлайну ДЗ створює `pg_cron` кожні 5 хвилин.

Секрети інтеграцій (токен бота, Google OAuth, ключ Anthropic) адміністратор вводить у кабінеті (**Налаштування → Інтеграції**). Вони зберігаються зашифровано у Supabase Vault і недоступні з браузера.

## Фаза 0: групові пробні та оплата викладачів

- **Пробний у міні-групі (FR-26)**: таблиця `lesson_leads` — один пробний урок для 1–4 заявок. Менеджер створює новий пробний або додає заявку до наявного (CRM → заявка → «Призначити»). Відмітка «Був / Не був» оновлює статус кожної заявки окремо; бот нагадує лідам за годину й повідомляє про перенесення чи скасування.
- **Оплата уроків (FR-25)**: сторінка **Оплата уроків** рахує нарахування з відвідуваності: група — 180 ₴ + 30 ₴ × присутніх, індивідуальний — 250 ₴, пробний — 150 ₴ (індивідуальний) або 90 ₴ за кожного ліда, що прийшов (міні-група). Ставки редагує адміністратор; є експорт CSV. Викладач бачить лише свої уроки.
- **Ціни на сайті** — з бізнес-плану (розділ 7.5): міні-група 300/270 ₴, індивідуально 450/420 ₴, НМТ 300/270 ₴ за урок (помісячно / пакет). Джерело — `src/content/site.ts`; бот бере ті самі факти з `supabase/functions/_shared/school.ts`.

## ШІ-модуль

| Фаза | Функції | Прапорець у **ШІ-модуль** |
| --- | --- | --- |
| 1 | Чернетки перевірки ДЗ, підсумки уроків, профіль помилок учня, текстовий тренер, облік `ai_usage`, модерація | `review_enabled`, `lesson_enabled`, `tutor_enabled` (+ пілотні групи) |
| 2 | Скоринг ризику відтоку (SQL щоночі) з поясненням, щотижневі звіти батькам у Telegram за згодою | `risk_enabled`, `parent_reports_enabled` — **вимкнено** |
| 3 | Тест рівня для лідів, нічні відповіді бота | `level_test_enabled`, `night_reply_enabled` — **вимкнено** |

Принцип P1: ШІ лише готує чернетки — оцінки й підсумки публікує викладач. Чернетки перевірки зберігаються в окремій таблиці `submission_ai_reviews` (RLS гарантує, що учень не бачить оцінку ШІ до підтвердження; див. 6.3 документації). Текст практики зберігається 90 днів (cron), аудіо не зберігається. Викладач бачить підсумки й тексти практики своїх учнів, менеджери — лише підсумки; підозрілі сесії позначаються й надсилаються викладачу.

Витрати: кожен виклик пише рядок в `ai_usage` (токени, кеш, вартість за цінами з налаштувань). Ліміти — повідомлень і $ на учня за день, загальний денний бюджет школи. Щопонеділка адміністратор отримує звіт у Telegram. Моделі за замовчуванням: `claude-sonnet-5` (діалог, перевірка), `claude-haiku-4-5` (підсумки, класифікація); змінюються в налаштуваннях без деплою.

Не реалізовано свідомо: голосова практика (FR-18) — провайдер голосу обирається за результатами прототипу (ADR-08, відкрите питання 14.5); підсумки з транскриптів Meet (FR-21) — залежать від тарифу Google Workspace; онлайн-оплата (FR-24) — окремий документ після вибору еквайрингу.

## Перший запуск — чекліст

1. **Supabase → Authentication → URL Configuration**
   - Site URL: адреса сайту (`https://www.sealenglish.school`)
   - Redirect URLs: `https://<ваш-домен>/**` і `http://localhost:3000/**`
2. Відкрийте **`/setup`** і створіть акаунт адміністратора. Сторінка працює лише доки в школі немає жодного адміна.
3. Після цього в **Authentication → Sign In / Providers → Email** вимкніть «Allow new users to sign up»: акаунти створює менеджер у кабінеті.
4. **Кабінет → Інтеграції**:
   - вкажіть адресу сайту;
   - Telegram: створіть бота в @BotFather і вставте токен. Webhook, команди й опис налаштуються автоматично;
   - Google: створіть OAuth-клієнт (Web) у Google Cloud, додайте показаний redirect URI, збережіть Client ID і secret, натисніть «Підключити акаунт Google». Застосунок у Google Cloud переведіть у статус *In production*;
   - ШІ: вставте ключ Anthropic API (перевіряється одразу) і встановіть ліміт витрат в акаунті Anthropic.
5. **Кабінет → ШІ-модуль**: увімкніть модуль і потрібні функції фази 1, за потреби оберіть пілотні групи тренера (ADR-06: 2 пілотні + 2 контрольні групи).
6. **Кабінет → Оплата уроків → Ставки**: перевірте ставки викладачів.
7. **Налаштування → Підключити Telegram**: кожен менеджер і викладач підключає свій Telegram.
8. Юридичні сторінки: `src/app/privacy` (містить пункт про ШІ-провайдера — умова старту фази 1) і `src/app/offer`; реквізити — у `src/content/site.ts`.

## Розробка

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # статичний експорт у out/
npm run lint
npm run typecheck
```

Публічні змінні — у `.env.production` / `.env.development` (URL проєкту та publishable key Supabase, адреса сайту).

### Тести

- **RLS / бізнес-правила БД** (pgTAP, NFR-02): `supabase db start && supabase test db` — `supabase/tests/database/rls.test.sql` перевіряє доступ кожної ролі до кожної нової таблиці, оплату уроків, групові пробні.
- **Edge Functions**: `deno check supabase/functions/*/index.ts`, `deno lint`, модульні тести `SUPABASE_URL=http://localhost SUPABASE_SERVICE_ROLE_KEY=test deno test --allow-env supabase/functions/_tests/` (модерація, облік вартості, валідація відповідей ШІ, тест рівня).
- **CI** (`.github/workflows/ci.yml`): lint, typecheck, build, перевірка й тести функцій, міграції + pgTAP на кожен push.

### Бренд і маскот

- `python design/mascot/build_rig.py` — перегенерувати геометрію риґу з `design/mascot/seal-reference.png`
- `python design/mascot/preview_rig.py` — порівняння риґу з оригіналом (`design/mascot/out/compare.png`)
- `python design/brand/build_brand.py` — логотипи, іконки, фавікони, OG-зображення в `public/`

### Деплой

- **Сайт**: push у `main` → Wasmer збирає Next.js і публікує `out/`.
- **Edge Functions**: GitHub Action `.github/workflows/supabase-functions.yml` (ручний запуск, потрібен секрет `SUPABASE_ACCESS_TOKEN`) або `supabase functions deploy`.
- **Міграції БД**: `supabase/migrations`, лише вперед. Міграція `20260924120000_phase0_platform.sql` переносить лідів пробних уроків у `lesson_leads` і видаляє колонку `lessons.lead_id` — застосовуйте її разом із деплоєм функцій і сайту (стара версія кабінету читає цю колонку).
